# Performance Engineering Basics

## 1. この資料の目的

本資料は、Webシステムの性能試験を行う際に必要となる
性能要件、主要指標、ボトルネック確認観点を整理することを目的とする。

現在作成しているAI-Native Performance Engineering PoCでは、
p95 / p99 / error rate / RPSなどを用いて性能判定を行っている。

本資料では、それらの数値を単に計測するだけではなく、

- なぜその指標を見るのか
- どのように性能要件へ落とし込むのか
- 性能劣化が発生した場合にどこを確認するのか

を整理する。

---

## 2. 性能要件を決めるために必要な情報

性能要件は、技術者が任意に決めるものではなく、
実際の業務利用をもとに定義する必要がある。

主な確認項目は以下。

- 想定ユーザー数
- 最大同時ユーザー数
- ピーク時間帯
- 1ユーザーあたりの操作頻度
- API / 画面ごとの利用割合
- 目標レスポンスタイム
- 許容エラー率
- TPS / RPS
- データ量
- 将来の利用増加率

### 例

ECサイトの場合、

1. 1000人が同時アクセスする
2. 60%が商品検索
3. 30%が商品詳細閲覧
4. 10%が購入処理

といった利用モデルを作成し、
負荷試験シナリオへ落とし込む。

## 3. 主要な性能指標

### p95

全リクエストの95%が、この値以下の応答時間で処理されたことを示す。

平均値だけでは、一部の極端に遅いリクエストが見えにくいため、
ユーザー体験を見る際に利用する。

### p99

全リクエストの99%が、この値以下の応答時間で処理されたことを示す。

p95よりもテールレイテンシの確認に向いている。

### RPS

Requests Per Second。

1秒あたりに処理できたリクエスト数を表す。

baselineと比較してRPSが大きく低下した場合、
処理能力が低下している可能性がある。

### Error Rate

全リクエストに対して失敗したリクエストの割合。

レスポンスタイムが正常でも、
エラー率が高い場合は性能要件を満たしているとは言えない。

## 4. 性能試験で確認するリソース

性能劣化が発生した場合、
アプリケーションだけを原因と考えない。

以下の観点から切り分ける。

### CPU

確認事項：

- CPU使用率
- 高負荷時間帯
- 特定プロセスのCPU消費
- CPU飽和

### Memory

確認事項：

- メモリ使用率
- スワップ
- メモリリーク
- GC発生状況

### Disk I/O

確認事項：

- IOPS
- read / write latency
- ディスク使用率
- I/O wait

### Database

確認事項：

- SQL実行時間
- slow query
- 接続数
- connection pool
- lock
- index
- DB CPU / Memory

### Network

確認事項：

- latency
- bandwidth
- packet loss
- 外部サービスとの通信時間

## 5. 性能問題の基本的な切り分け

性能劣化を確認した場合、

観測事実
↓
仮説
↓
追加確認

の順で整理する。

### ケース1

観測事実：

- p95悪化
- CPU正常
- RPS低下
- DB接続数が上限付近

仮説：

DB connection pool待ちが発生している可能性。

追加確認：

- pool利用率
- connection wait time
- SQL実行時間
- DB lock

---

### ケース2

観測事実：

- CPU 95%
- error rate正常
- RPS頭打ち

仮説：

CPU飽和によって処理能力が制限されている可能性。

追加確認：

- プロセス別CPU使用率
- thread / worker数
- GC
- profiling結果

---

### ケース3

観測事実：

- p95正常
- error rate増加
- CPU / Memory正常

仮説：

アプリケーションエラーまたは外部依存サービスの失敗の可能性。

追加確認：

- application log
- HTTP status
- stack trace
- 外部API応答

---

## 6. AIを利用する場合の役割

AIには原因を断定させない。

AIの役割は、

- 観測結果の整理
- 原因候補の提示
- 追加確認項目の提案

までとする。

例：

NG

「DBが原因です」

OK

「DB connection pool待ちの可能性があります。
確認にはpool利用率、SQL実行時間、lock状況などが必要です。」
